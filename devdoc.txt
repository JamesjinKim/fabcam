  ● NPU vs GPU vs CPU - 독립적인 처리 유닛

  하드웨어 아키텍처 차이

  NPU (Neural Processing Unit)
  - 독립 칩: Hailo-8은 별도 M.2/PCIe 카드로 장착
  - 전용 회로: AI 연산(행렬곱, 컨볼루션)에 특화된 ASIC
  - 메모리: 자체 온칩 메모리 (Hailo-8: 32MB SRAM)
  - 병렬성: 수천 개 MAC(Multiply-Accumulate) 유닛

  GPU (라즈베리파이 5 - VideoCore VII)
  - 통합형: BCM2712 SoC 내부에 포함
  - 범용 병렬: 그래픽 + 비디오 인코딩/디코딩
  - 메모리: 시스템 RAM 공유 (GPU 메모리 스플릿)
  - 용도: H.264 인코딩, 이미지 처리, OpenGL

  CPU (Cortex-A76 × 4)
  - 중앙 처리: 범용 연산, 시스템 제어
  - 순차 처리: 복잡한 로직, 분기 처리
  - 메모리: L1/L2/L3 캐시 + 시스템 RAM
  - 용도: 애플리케이션 로직, I/O 제어

  상호 연관성과 데이터 흐름

  [카메라] → [CPU: 캡처] → [GPU: 전처리/인코딩] → [NPU: AI 추론]
                  ↓                    ↓                    ↓
             [시스템 제어]      [H.264 스트리밍]     [객체 감지]

  실제 작업 분담 예시

  현재 fabcam (NPU 없음)
  # CPU: 10-15% - FastAPI 서버, 로직 처리
  # GPU: 20-30% - H.264 인코딩, MJPEG 변환
  # NPU: 0% - 사용 안 함

  Hailo 추가 후
  # CPU: 15-20% - 전처리, 후처리, 바운딩박스 그리기
  # GPU: 20-30% - 동일 (비디오 인코딩)
  # NPU: 60-80% - YOLO11 추론 전담

  병목 현상과 밸런싱

  독립 동작 (좋은 경우)
  - NPU가 AI 추론하는 동안 GPU는 계속 비디오 인코딩
  - CPU는 네트워크 I/O와 전체 조율만 담당
  - 각자 역할이 분리되어 효율적

  데이터 전송 병목 (주의할 점)
  # 비효율적 - CPU가 중간 다리 역할
  Frame → CPU → NPU → CPU → GPU

  # 효율적 - Zero-copy, DMA 활용
  Frame → Shared Memory → NPU/GPU 동시 접근

  실제 코드에서의 최적화

  class OptimizedPipeline:
      def __init__(self):
          # 각 처리기 독립 초기화
          self.npu = HailoRT()  # NPU - AI 추론
          self.gpu_encoder = H264Encoder()  # GPU - 비디오
          self.cpu_pool = ThreadPool(2)  # CPU - 제어

      async def process_frame(self, frame):
          # 병렬 처리 - 서로 간섭 없음
          tasks = [
              self.gpu_encoder.encode(frame),  # GPU 작업
              self.npu.detect(frame),          # NPU 작업
          ]
          # CPU는 조율만
          results = await asyncio.gather(*tasks)
          return results

  핵심 요약

  - 물리적 독립: NPU는 별도 하드웨어, GPU/CPU와 자원 경쟁 없음
  - 기능적 협업: 데이터는 공유하지만 연산은 독립 수행
  - 병목 위험: 데이터 전송 경로 최적화 필요 (DMA, 공유 메모리)
  - 최적 활용: CPU 15%, GPU 30%, NPU 70% = 전체 시스템 효율적 운영

  NPU 추가는 기존 CPU/GPU 부하를 늘리지 않고 AI 기능을 추가하는 가장 효과적인
   방법입니다.
